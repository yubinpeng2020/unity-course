角色移动与视角

用 Character Controller 实现更高效的角色移动，配上第一人称的摄像机跟随与鼠标视角控制
授课教师彭堉斌
学校汕头职业技术学院

本节学习目标

🎯理解 Character Controller 相比刚体移动的优势
⬆️用 Character Controller 实现玩家移动与跳跃（含重力）
🎥把摄像机挂为 Player 的子节点实现跟随
📝用 PlayerRotate 脚本实现鼠标控制视角

角色移动的常见做法

前面两节，我们已经让角色"动"起来两次，但用的办法并不一样。Unity 里让一个角色移动，常见的做法有三种：

① 直接改坐标（课件11）

  • 做法：用 transform.Translate 每帧把坐标挪一点
  • 优点：逻辑最简单，想走哪就走哪
  • 局限：没有碰撞响应，撞上墙会穿模

② 刚体移动（课件12）

  • 做法：给角色加 Rigidbody，用 AddForce 或速度驱动
  • 优点：有重力、有真实碰撞
  • 局限：角色会滑走、被撞翻，还要靠 Constraints 补救

③ 角色控制器（本课）

  • 做法：用 Character Controller 组件，靠 Move 方法移动
  • 优点：为"人"而生——指哪走哪、贴墙不穿、能上台阶
  • 代价：不参与物理，被撞不会飞出去
三种做法没有绝对的好坏，关键看对象是谁。接下来，就看为玩家角色专门设计的那一种。

角色控制器 Character Controller · GetComponent

把 Character Controller 加到 Player 上，最直观的变化是：模型外面多出了一个胶囊形的线框——看着就像给角色套了个椭圆边框。它就是 Character Controller 自带的碰撞体，角色会被什么挡住，都由这个线框说了算。

这个组件是 Unity 专门为角色准备的，适合第一 / 第三人称的角色——它把角色的碰撞体和移动都接管了过来。具体有什么特点，接着往下看。

它的特点

  • 不参与物理模拟：不会被撞飞，也不会自己滑走
  • Move 方法精确控制：走多远、往哪走，完全由代码决定
  • 自带碰撞检测：挡得住墙，又不会像刚体那样弹开
  • 台阶与斜坡：用 Step Offset 跨越台阶，用 Slope Limit 控制可攀爬的坡度

添加与参数

选中 Player → Add Component → Character Controller。它内置胶囊碰撞体，所以原来的 Capsule Collider 可以移除。下面是它各项参数的作用，逐个认识一下：

参数作用
斜度限制（Slope Limit）能爬上去的最大坡度。超过这个角度，角色会滑下来、上不去。默认 45
每步偏移量（Step Offset）能自动迈上去的台阶高度（米）。0.3 ≈ 30cm 以下的台阶直接走过去，不用跳
蒙皮宽度（Skin Width）碰撞体外面的一层"皮肤"，让贴墙时留一点缝隙，避免卡住或抖动。默认 0.08
最小移动距离（Min Move Distance）每帧移动小于这个距离就不动，用来过滤极小的抖动。默认 0.001
中心（Center）胶囊相对于角色原点的位置。默认 Y = 0 时胶囊偏上、包不住角色，把它调到 0.9 就正好对准身体
半径（Radius）胶囊的粗细（半径），取 0.5
高度（Height）胶囊的总高度（含上下两端的半球）。默认 2 比角色还高，调到 1.85 刚好贴住角色
⚠️ 上一节给角色加的刚体（Rigidbody）和 Capsule Collider 要一起移除——Character Controller 本身就是个胶囊碰撞体，位移也由它自己算：留着刚体会和它抢着算位移，再挂碰撞体则容易让角色卡住。

移除组件的流程

想把刚体、Capsule Collider 删掉，两步就行：

  1. 点组件右上角的设置按钮（⋮）
  2. 在弹出的菜单里选「移除组件」，组件就没了

Character Controller 的好处

把上面的特点连起来看：角色想怎么走就怎么走，撞墙被稳稳挡住而不会穿模，遇到台阶和斜坡还能自己上去——这几件事，正是上一节用刚体时最别扭的地方。

一句话记住：球和箱子用刚体（被推着走），走路的人用 Character Controller（自己走）。

跳跃的思路

移动管的是水平方向，跳跃管的是竖直方向——两件事都用 controller.Move，只是方向不同。要让角色跳起来，先想明白三件事：

  • 竖直速度要自己存：用一个变量 verticalVelocity 记住当前是往上还是往下，每帧被重力往下拉
  • 起跳速度是算出来的：想跳多高，由 v = √(2·h·g) 反推——跳 2 米就是 √(2×2×9.81) ≈ 6.26
  • 落地才能再跳：controller.isGrounded 为 true 才允许起跳，否则在空中还能一直跳

完整脚本：PlayerMove（移动 + 跳跃）

把脚本挂到 Player 上，角色走和跳都靠 controller.Move：

CSHARP
using UnityEngine;

public class PlayerMove : MonoBehaviour {
    private CharacterController controller;  // 角色控制器
    public float moveSpeed = 10f;            // 移动速度
    public float jumpHeight = 2f;            // 想跳多高（米）
    public float gravity = 9.81f;            // 重力加速度
    private float verticalVelocity;          // 竖直方向当前的速度
    private bool isJumping;                  // 是否处于跳跃状态

    void Start() {
        controller = GetComponent<CharacterController>();
    }

    void Update() {
        PlayerMovement();                    // 管前后左右
        PlayerJump();                        // 管跳跃与下落
    }

    // 水平移动：前后左右
    private void PlayerMovement() {
        float horizontal = Input.GetAxis("Horizontal");
        float vertical   = Input.GetAxis("Vertical");
        Vector3 move = transform.right * horizontal + transform.forward * vertical;
        controller.Move(move * moveSpeed * Time.deltaTime);
    }

    // 跳跃与重力
    private void PlayerJump() {
        if (!controller.isGrounded || isJumping) {           // 不在空中就没事，离地或跳跃中受重力
            verticalVelocity -= gravity * Time.deltaTime;
            controller.Move(Vector3.up * verticalVelocity * Time.deltaTime);
        } else {                                             // 稳稳站在地上
            isJumping = false;
            verticalVelocity = 0;
        }
        if (controller.isGrounded && Input.GetButtonDown("Jump")) {   // 站地上 + 按下跳跃键
            isJumping = true;
            verticalVelocity = Mathf.Sqrt(2f * jumpHeight * gravity);
        }
    }
}

代码讲解

  1. 字段：controller 是角色控制器，设成 private——它由代码自己 GetComponent 拿到，不用在检查器（Inspector）里拖；moveSpeed / jumpHeight / gravity 设成 public，可以直接在检查器（Inspector）里调；verticalVelocity、isJumping 只在脚本内部用，也设成 private
  2. 获取自身组件：controller = GetComponent<CharacterController>()——GetComponent<T>() 就是在脚本所在的这个物体（Player）自己身上找类型为 T 的组件，找到后把引用交给 controller
  3. 每帧两件事：Update 里只调两个方法——PlayerMovement 管前后左右，PlayerJump 管跳跃和下落
  4. 水平移动：Input.GetAxis 取键盘输入，transform.right / transform.forward 把它拼成"角色自身"的方向，再交给 Move；乘 Time.deltaTime 是为了不受帧率影响
  5. 什么时候受重力：!controller.isGrounded || isJumping——只要离了地或正处于跳跃中，就每帧减重力、并沿 Vector3.up 走一步
  6. 起跳：站在地上（isGrounded）且按下跳跃键时，把 isJumping 记成 true，并用 Mathf.Sqrt(2f * jumpHeight * gravity) 算出初速度（跳跃键默认绑定空格）
  7. 为什么要 isJumping 这个标志：按下跳跃键的那一帧角色还站在地上，如果只看 isGrounded，下一帧就会把速度清零、人根本起不来；用标志"记住正在跳"，就能一直往上走，直到落地才复位
  8. 落地：isGrounded 且不在跳跃中时，走 else——isJumping 复位、竖直速度清零，角色稳稳站住
  9. 下落越来越快：正是靠每帧减掉的 gravity * Time.deltaTime 一点点累积，速度才越掉越快——这也是不能用固定值代替变量的原因
💡 重点：GetComponent<T>() —— 从自己身上拿组件。它只在脚本所在的这个物体上查找：脚本挂在 Player 上，拿到的就是 Player 身上的 Character Controller。要是 Player 上没挂这个组件，它会返回 null，后面的 controller.Move 就会报空引用——所以"脚本挂谁身上"很关键。
⚠️ 竖直速度必须用变量累加，不能每帧直接写成 -gravity——那样只是匀速下落，没有"越掉越快"的手感；另外"是否在跳"要用 isJumping 记下来，否则起跳那一帧就会被判成落地、速度清零。

还差一步：让镜头跟住角色

角色现在能走能跳了，可镜头还钉在原地——角色一跑远，画面里就看不见它了。游戏里不管是第一人称还是第三人称，镜头都是跟着角色走的。下一页就解决两件事：先让摄像机跟住角色，再让鼠标把视角转起来。

摄像机跟随与鼠标视角 · GetComponentInChildren

先看这一节要做成的效果：镜头始终跟着角色走，鼠标一动还能自由环视——左右转头、抬头低头，画面都跟着变，人走到哪儿镜头就跟到哪儿。这就是我们在游戏里熟悉的第一人称视角。接下来分两步把它做出来：先让摄像机跟住角色，再让鼠标把视角转起来。

最简单的跟随方式：把 Main Camera 直接作为 Player 的子节点，并把摄像机位置重置到合适高度（第一人称一般放在角色眼睛的高度）。

为什么这样就够了？因为子对象会跟着父对象一起移动、旋转——Player 走到哪，挂在它下面的摄像机自然就跟到哪，一行代码都不用写。

不过，摄像机只是跟着角色平移，镜头朝向一直是固定的——想看看左右两边，还得让角色自己转过去。要像游戏里那样用鼠标自由环视，就得再加一个脚本，让鼠标的移动变成旋转。

用鼠标转动视角

PlayerRotate 脚本：鼠标左右移动时旋转玩家，实现水平环视；鼠标上下移动时转动摄像机，并用 Mathf.Clamp 把俯仰角限制在 ±60°，防止镜头翻过去。脚本挂在 Player 上，玩家和摄像机都在脚本里自动拿到，不用手动拖。

CSHARP
using UnityEngine;

public class PlayerRotate : MonoBehaviour {
    public float rotateSpeed = 180;          // 鼠标灵敏度
    [Range(2, 4)] public float rotateRatio = 3;
    private Transform playerTrans;           // 玩家（要被旋转）
    private Transform mainCameraTrans;       // 摄像机（要上下转动）
    private float xRotateOffset;             // 摄像机当前的俯仰角

    void Start() {
        playerTrans = transform;                                        // 挂脚本的就是玩家
        mainCameraTrans = GetComponentInChildren<Camera>().transform;   // 子对象里的摄像机
    }

    void Update() {
        PlayerRotateControl();
    }

    private void PlayerRotateControl() {
        float mouseX = Input.GetAxis("Mouse X");
        float mouseY = Input.GetAxis("Mouse Y");
        playerTrans.Rotate(Vector3.up * mouseX * rotateSpeed * rotateRatio * Time.deltaTime);
        xRotateOffset -= mouseY * rotateSpeed * rotateRatio * Time.deltaTime;
        xRotateOffset = Mathf.Clamp(xRotateOffset, -60, 60);
        Vector3 camAngle = mainCameraTrans.localEulerAngles;   // 沿用原来的 Y、Z
        Vector3 v = new Vector3(xRotateOffset, camAngle.y, camAngle.z);
        mainCameraTrans.localRotation = Quaternion.Euler(v);
    }
}

代码讲解

  1. 挂载与取引用：脚本挂在 Player 上（和 PlayerMove 同一个对象）；Start 里把两个引用都自己找出来——playerTrans = transform（挂脚本的就是玩家自己），相机见下一条
  2. 获取子节点上的组件：mainCameraTrans = GetComponentInChildren<Camera>().transform——GetComponentInChildren<T>() 会先看自己，再往所有子物体里逐层找，返回第一个类型为 T 的组件；这里取到 Camera 之后，再用 .transform 拿它的 Transform
  3. 鼠标灵敏度：rotateSpeed 是基础速度，[Range(2, 4)] 让 rotateRatio 在检查器（Inspector）里显示成 2~4 的滑杆，课堂上好调
  4. 左右环视：Input.GetAxis("Mouse X") 取鼠标左右移动量，乘上速度交给 playerTrans.Rotate(Vector3.up * …)——转的是玩家，作为子对象的摄像机自然跟着转
  5. 上下俯仰：Mouse Y 累加进 xRotateOffset（用 -=，所以鼠标前推时镜头往下压），再用 Mathf.Clamp 卡在 ±60°，抬头低头都不会翻过去
  6. 应用旋转：只把俯仰角放进欧拉角的 X，Y、Z 沿用摄像机原来的值，再赋给 localRotation——这样头只上下转，画面不会歪
💡 重点：GetComponent 只找自己，GetComponentInChildren 才会往子物体里找。上一页已把 Main Camera 挂成了 Player 的子节点，所以这里能一路往下找到它；如果相机没挂在 Player 下面，这段会返回 null，那就得改用 Camera.main.transform 按 MainCamera 标签去找。

作业 · 第一人称角色的移动与视角

基本要求

  • 沿用场景：一个 Player，身上挂着 Character Controller 与 PlayerMove，刚体与 Capsule Collider 已移除
  • 能走能跳：WASD 前后左右移动、空格跳跃；水平方向用 controller.Move 驱动，竖直方向自己累加重力
  • 镜头跟住角色：把 Main Camera 挂成 Player 的子对象，位置放到角色眼睛高度
  • 鼠标能环视：PlayerRotate 脚本挂在 Player 上，鼠标左右移动转玩家、上下移动转摄像机，俯仰角限制在 ±60° 以内

核心要求

  • 起跳站得住：只在 controller.isGrounded 为真时响应跳跃键，并用标志把"正在跳"记下来——否则起跳那一帧就会被判成落地、人根本起不来
  • 镜头不歪：低头抬头时画面只上下转、不左右歪——只把俯仰角写进欧拉角的 X，Y、Z 沿用摄像机原来的值
  • 换台电脑也一样：所有每帧的移动与旋转都要乘 Time.deltaTime
  • 手感要调：把 moveSpeed、jumpHeight、rotateSpeed 调到顺手，并在注释里写清你改了哪几个、为什么

本次作业（必做）：冲刺 —— 按住 Shift 速度翻倍

走、跳、转视角在第 3、4 页已经完整写过一遍，这次不动它们，只在 PlayerMove 的移动速度上做文章：按住 Shift 用双倍速度跑，松开立刻回到普通速度——判断要用 Input.GetKey（按住持续为真），别用只在按下那一帧为真的 GetKeyDown。

改动很小——加一个字段，再在 PlayerMovement() 里加两行、改一行：

CSHARP
// ① 在字段区加一个：冲刺倍数（2f = 两倍速），可用 public 暴露到检查器调
public float runMultiplier = 2f;

// ② 先定当前速度：按住 Shift 就翻倍，松开自动回到原速
float speed = moveSpeed;
if (Input.GetKey(KeyCode.LeftShift)) speed *= runMultiplier;

// ③ 再用这个 speed 算水平位移（原来乘的是 moveSpeed，这里换成 speed）
Vector3 move = transform.right * horizontal + transform.forward * vertical;
controller.Move(move * speed * Time.deltaTime);

要看到的效果：不按 Shift 是正常走路，按住 Shift 明显加速跑；一松开立马回到原来的速度，跳跃和鼠标环视都不受影响。

挑战（选做）

  • ① 落地反馈：在落地那一刻用 Debug.Log 打印下落速度，看看"从多高落下会摔多快"
  • ② 参数滑杆：给 jumpHeight 加一个 [Range(1, 8)]，在检查器里用滑杆调跳跃高度，找出手感最好的一档
⚠️ 在代码里改 public 变量的默认值，不会同步到已经挂好脚本的组件上——要让新值生效，点组件右上角的 ⋮ → 重置（Reset），或者直接在检查器里改那一栏。
