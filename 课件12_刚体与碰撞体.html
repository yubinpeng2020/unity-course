刚体与碰撞体

给游戏对象加上刚体与碰撞体，让它拥有真实的物理表现——会下落、会被挡住、落地站得稳，并在此基础上实现跳跃
授课教师彭堉斌
学校汕头职业技术学院

本节学习目标

🎯理解 Rigidbody 刚体：让对象进入物理模拟（重力、受力）
📝理解 Collider 碰撞体：检测碰撞、避免穿模
✅把刚体 + 碰撞体结合，实现对象落地站稳
🚀综合应用：用刚体实现跳跃

Rigidbody 刚体

先看效果：小动物为什么会自己掉下来？

看上面的动图：几只小动物从空中掉下来、稳稳落在地形上——我们并没有写"往下掉"的代码，它们却像现实里一样被重力拉了下去，落到地面还有碰撞效果，不会穿过去。

这种会下落、被地面挡住、站得稳的真实感，靠的是 Unity 的两个物理组件配合：Rigidbody（刚体）负责让对象受力与运动，Collider（碰撞体）负责检测碰撞、避免穿模。接下来两节，我们先讲刚体，再讲碰撞体——这一节先认识刚体。

添加方式

选中对象 → Add Component（添加组件） → Rigidbody（刚体）。

简单说，添加刚体组件，就是给游戏对象赋予"物理属性"：一旦挂上它，这个对象就进入了 Unity 的物理模拟——会受重力、能被撞飞、能受力运动。下面这张属性面板里的每一项（质量、阻力、是否受重力……），就是它的"物理参数"。

刚体的物理属性

属性作用
Mass 质量受力时的加速度大小——越重越"沉"
Drag 阻力运动时速度衰减（空气阻力）
Angular Drag 角阻力旋转时角速度衰减
Use Gravity 重力是否受重力影响（默认勾选，所以会下落）
Is Kinematic 运动学不受力 / 扭矩影响，但可用脚本直接控制位置旋转
给对象加了 Rigidbody，它就"活"了——会下落、会被推。

但有个问题：对象只有刚体、没有碰撞体，会"穿模"

刚体让对象受重力下坠，可如果对象只有刚体、没有碰撞体，就会直接穿过地面一直往下掉——物理引擎根本不知道"地面在哪、该在哪被挡住"。这种现象叫穿模。

要解决"穿过去"的问题，还需要一个组件——Collider（碰撞体）：它负责检测碰撞、把物体挡在地上。下一节我们就讲碰撞体。

Collider 碰撞体

为什么要加碰撞体：让对象"撞得到、挡得住"

上一节我们看到：对象只有刚体、没有碰撞体时，会直接穿过地面（穿模）。Collider（碰撞体）就是来解决这个问题的——它负责检测物体之间的接触或碰撞：有了它，地面才能"挡住"下落的对象，物体之间也能互相撞到而不是穿过彼此。

添加方式

选中对象 → Add Component（添加组件） → Box Collider（盒型碰撞体）。

常见碰撞体类型

  • Box Collider（盒型碰撞体）：立方体，适合墙、门、箱子
  • Sphere Collider（球形碰撞体）：球形，适合球类、星球
  • Capsule Collider（胶囊形碰撞体）：胶囊形，适合角色身体（贴合人体，移动自然）

碰撞体是什么：一层看不见的边框

换个好懂的说法：碰撞体就是给对象套上一层看不见的边框（碰撞范围）。上面这些形状（盒子 / 球 / 胶囊），就是不同对象用的边框。物理引擎其实不看模型的精细外形，只判断这些边框有没有碰到一起——边框挨上了，就算"撞到"；没挨上，就当没接触。所以碰撞准不准，全看这层边框包得合不合理。

常见属性

以盒型碰撞体（Box Collider）为例，属性面板共有 6 项：

  • 编辑碰撞器（Edit Collider）：按钮，点击后进入边框编辑模式，可手动拖动调整边框（下面"调整碰撞体边框"会用到）
  • 是触发器（Is Trigger）：勾选后碰撞体变成"触发器"——只检测进入 / 停留 / 离开，不产生物理反应（不挡住、不碰撞）
  • 提供接触（Provide Contacts）：勾选后，触发器在检测进入 / 离开时也会生成接触点，可获取更详细的接触信息
  • 材质（Material）：物理材质，决定摩擦（动摩擦、静摩擦）和弹性
  • 中心（Center）：边框中心相对对象的位置（X / Y / Z）
  • 大小（Size）：边框在 X / Y / Z 三个方向上的尺寸

调整碰撞体边框

添加 Collider 后，点击"编辑碰撞器"按钮手动调整边框，让它正好包裹模型：

  1. 点击"编辑碰撞器"按钮进入编辑
  2. 鼠标按住盒子某个面的中心点（方块手柄）拖动，可调整该方向的大小；按住边框整体拖动，可调整位置
  3. 再次点击按钮退出编辑
理想状态：碰撞体正好包裹住整个模型——太大容易"隔空碰撞"，太小又会穿模。

动手：给人物加碰撞体并调整边框

给人物模型也加上碰撞体后，常常发现边框没有很好地包裹住人物——比如四肢露在外面、或整体偏大偏小。

这时就用到上面说的"编辑碰撞器"：点按钮进入编辑，按住每个面的中心点拖动，把边框调到正好贴住人物。

小技巧：把视图切到正交（iso）视角，再配合右上角的 Gizmo 导航器 转动观察角度，从各个方向确认边框是否贴住人物，调整起来会非常方便。

试试看：人物去撞动物，却"穿模"了

给人物加上碰撞体和 Move3D 脚本组件后，操纵它移动去撞动物模型，却发现人物直接穿了过去——明明都有碰撞体，为什么还会穿模？

原因是：这时人物身上只有碰撞体、还没有刚体。物理引擎要"挡住"一个能动的物体，得由刚体托管它；只挂碰撞体、又用代码直接挪坐标，是不会被挡住的。下一页我们就把刚体 + 碰撞体合起来——先讲物体之间怎么碰撞，再讲落地和跳跃。

刚体 + 碰撞体 · 物体碰撞与落地

物体之间的碰撞

给人物和动物都加上刚体 + 碰撞体，再用代码移动人物去撞动物——这次人物不会穿过去了：两个碰撞体碰到一起，物理引擎就把它们挡住（或互相反弹、推动）。这正是"两个都有碰撞体的物体之间的交互"。

碰撞要能发生，需要两个条件：

  • 两个对象都有 Collider；
  • 至少一个有 Rigidbody（由它驱动运动）。

两者合起来：先"落地"

刚体让对象受重力下坠，碰撞体让对象不穿模——把两者合起来，对象就会落到地面并稳稳站住：重力一直往下拉，地面的碰撞体把它挡住，于是停在接触面上。

注意组件的搭配：人物和动物都要加 刚体 + 碰撞体——既能受力下落、又能被地面挡住；而地面只要碰撞体就够了，它本来就不用动，只负责"挡住"掉下来的对象。

碰撞发生的那一刻，Unity 会自动"喊"你一声

角色落到地面上、或者撞到别的物体——这个"碰上了"的瞬间，Unity 会自动调用一个固定名字的函数，叫 OnCollisionEnter：

CSHARP
using UnityEngine;

public class CollisionLogger : MonoBehaviour
{
    // 碰撞发生的瞬间，Unity 会自动调用这个函数
    // other：撞上来的那个物体（下面用它的名字打印）
    void OnCollisionEnter(Collision other)
    {
        // 打印出被撞到的那个物体的名字
        Debug.Log("撞到了：" + other.gameObject.name);
    }
}

把这段脚本挂到角色上再运行：角色一碰到东西，Console（控制台）窗口就会打印出对方的名字。

  • 不用我们去调用——只要把名字写成 OnCollisionEnter，Unity 自己会在碰撞发生的那一刻调用它（这类"到点自动执行"的函数叫回调）。
  • 触发条件就是上一张卡的两个条件：两个对象都有碰撞体，且至少一方有刚体；否则碰不上，也就不会调用。
  • 括号里的 other 是被撞到的那个对象的信息，通过 other.gameObject.name 就能拿到它的名字（标签、位置等信息也都能取）。

它能干什么？最直接的用法就是判断"我是不是碰到地面了"——下一页做跳跃时，我们就靠它记住角色有没有站在地面上，避免在半空连跳。

刚体 + 碰撞体 · 实现跳跃

回顾课件11：键盘控制移动

在课件11 里，我们用 Move3D 脚本，靠 Input.GetAxis 读取键盘的 前后左右 输入，再用 transform.Translate 让角色移动。那时角色还没有刚体和碰撞体，"移动"只是单纯改坐标——没有重力、不会下落、也不会被挡住。

到了本课件，我们给角色加上 刚体（受重力）+ 碰撞体（被挡住），"移动"就和物理绑在了一起：角色既能按键盘走，又会受重力下落、被地面和别的物体挡住。换句话说，课件11 教会我们"怎么接收键盘来移动"，本课件在这个基础上，让移动有了"物理真实感"。

下面先梳理一下：游戏里角色常见的移动方式都有哪些。

游戏人物常见的移动方式

几乎所有游戏角色都离不开下面几种移动，区别主要在"怎么动、受不受物理影响"：

  • 匀速行走：以固定速度前后左右走（课件11 的 GetAxis 写法就能实现）
  • 加速跑：按住 Shift 等键提速（在行走速度基础上乘一个系数）
  • 重力下落：不主动控制时，被重力拉着往下掉，落到地面才停
  • 跳跃：给一个向上的力弹起，冲量用完再被重力拉回——本课件接下来专门讲
  • 平滑移动 / 缓动：起步慢慢加速、停下慢慢减速，比"瞬间达到全速"更自然（通常用阻尼或插值实现）

其中行走、跑我们已经会了；重力下落靠刚体自动完成；剩下跳跃，只要再解决"怎么判断站在地面、别在半空连跳"，就能做出来——本页接下来就来实现它。

怎么实现跳跃

落地站稳之后，就能做游戏里最常见的动作——跳跃：

  • 跳起来：按空格时，给刚体一个向上的冲量，人就被"弹"上去；
  • 落下来：冲量用完，重力立刻接管，把人往下拉——下落不用我们写一行代码；
  • 站得住：地面有碰撞体，落下来会被挡住，人就稳稳站在地面上。

跳跃的"上"和"下"全是物理引擎在算，我们只负责在按空格那一瞬间给一个力。

先看个问题：站在半空中也能一直跳

按空格把角色弹起来，人还在半空没落下来时再按一次空格——它又往上弹了一次；一直按，就一直往上弹，角色能凭空飞上天。

所以跳跃必须加一句判断：只有"站在地面"时，才允许起跳。那接下来的问题就是——我们要怎么知道"自己有没有站在地面"？

怎么判断"站在地面"

用一个变量记住"现在是不是站在地面上"：一起跳，就记成已离地；一碰到地面，再记成站住了。按空格时先看一眼它——如果还是"已离地"，角色就不会有反应。

那怎么知道"碰到了地面"？用的正是前面刚学的碰撞体：碰撞回调 OnCollisionEnter 会在角色碰到东西的那一刻自动执行，我们就在里面把变量记成"站住了"。

完整代码：Move2D_Jump

在课件11 的移动脚本基础上加一步——加上跳跃（水平移动沿用课件11 的 transform.Translate，不改）。角色要有 Rigidbody + Collider、地面要有 Collider；刚体不用手动拖，脚本会在 Start() 里自己获取：

CSHARP
using UnityEngine;

public class Move2D_Jump : MonoBehaviour
{
    private Rigidbody rb;         // 角色的刚体，Start 里自动获取
    public float disPreSec = 6f;  // 水平移动速度（单位/秒）
    public float jumpForce = 5f;  // 跳跃冲量：越大跳得越高

    private bool isGrounded = true; // 是否站在地面上

    void Start()
    {
        rb = GetComponent<Rigidbody>();   // 从"自己身上"取出刚体组件
    }

    void Update()
    {
        // ① 水平移动：前后左右走（沿用课件11 的 Translate 写法）
        float horizontal = Input.GetAxis("Horizontal"); // A/D 或 ←/→
        float vertical   = Input.GetAxis("Vertical");   // W/S 或 ↑/↓
        Vector3 move = new Vector3(horizontal, 0, vertical);
        transform.Translate(move * disPreSec * Time.deltaTime);

        // ② 跳跃：站在地面时按空格，给刚体一个向上的冲量
        if (Input.GetKeyDown(KeyCode.Space) && isGrounded)
        {
            rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse);
            isGrounded = false;   // 已离地，空中不能再跳
        }
    }

    // ③ 落地判定：碰到地面（碰撞体）就重新允许起跳
    // other：撞上来的那个东西，这里用不到，但 Unity 按这个签名调用，不能删
    void OnCollisionEnter(Collision other)
    {
        isGrounded = true;
    }
}

代码逐行解释

  • private Rigidbody rb; —— 存放角色的刚体组件；这里不用 public，因为值由脚本自己取，不需要在 Inspector 里暴露。
  • void Start() { rb = GetComponent<Rigidbody>(); } —— 游戏开始时，在脚本所在的这个游戏对象身上查找 Rigidbody 并交给 rb；尖括号里写要找的组件类型。只取一次，之后 Update 里直接用。⚠️ 前提是角色身上确实挂着 Rigidbody，否则取到的是空值。
  • transform.Translate(move * disPreSec * Time.deltaTime) —— 按每秒 disPreSec 个单位移动：乘 Time.deltaTime 把"每秒"换算成"这一帧该走多少"，这样不同帧率下速度才一致。（垂直方向不用我们管——下落交给重力、起跳交给冲量。）
  • Input.GetKeyDown(KeyCode.Space) —— 只在按下空格的那一帧返回 true（按住不会连发）；配合 isGrounded，只有站在地面时才能起跳。
  • rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse) —— 给刚体施加一个向上的冲量：Vector3.up 是正上方，jumpForce 决定跳多高，ForceMode.Impulse 表示"瞬间一次性"加力，而不是持续地推。
  • isGrounded = false; —— 起跳后立刻标记"已离地"，这样在空中再按空格也不会重复加力。
  • void OnCollisionEnter(Collision other) —— 碰撞回调：脚本所在对象刚碰到别的碰撞体时自动调用。角色落回地面时触发，把 isGrounded 设回 true，就又能起跳了。

补充：刚体也可以手动拖拽赋值

除了让脚本自己获取，还有另一种更直白的写法：把 rb 声明成 public Rigidbody rb;，再在 Inspector 里把角色身上的 Rigidbody 拖到这个格子上。

  • 两种写法效果完全一样——都是让 rb 指向角色自己的刚体组件。
  • 区别只在谁来赋值：拖拽是在 Inspector 里手动做；GetComponent 是脚本在 Start() 里自己做。
  • 用代码获取更省心：脚本挂上去就能跑，不怕漏拖——一旦忘拖，rb 就是空的，用到它就会报空引用错误。
💡 跳跃的"上"和"下"都交给物理引擎——我们只在按空格那一瞬间给一个向上的冲量，其余由重力和地面的碰撞体完成。动手前记得：① 角色要有 Rigidbody + Collider、地面要有 Collider；② 把课件11 挂在角色上的旧移动脚本移除或取消勾选，免得两个脚本同时控制角色。

刚体 + 碰撞体 · 撞到东西会倒怎么办

问题：撞到东西，人物会倒

用键盘操纵角色去撞动物、或者撞到别的物体——会发现角色被撞得东倒西歪，甚至直接"啪"地倒在地上，再也站不起来。

原因：刚体不只管位置，还管旋转

刚体负责的是角色整个"物理身体"——不只是位置和速度，还有旋转。碰撞的那一刻会产生力，这个力不只把人弹开，也会让身体绕轴转起来；而角色模型是"站着"的，一转头脚就翻过去，看起来就是倒下。

我们要的效果是：角色只平移、不翻滚。

解决：用约束（Constraints）冻结旋转

选中角色，在 Rigidbody 组件里找到 Constraints（约束），展开后有两组：冻结位置（Freeze Position）、冻结旋转（Freeze Rotation）。

勾选冻结旋转的 X 和 Z——角色就不会再前后、左右翻倒，只剩下平移。

Y 轴先留着：以后要让角色转身、朝向移动方向时，就靠它。

⚠️ 别去勾"冻结位置（Freeze Position）"——那是把角色的移动锁死，勾上之后连走都走不了。

作业 · 给角色加上物理真实感（落地 + 跳跃）

基本要求

  • 搭场景：一个地面（Plane，自带 Mesh Collider）+ 一个角色（Cube / Capsule），角色悬空摆放（离地一段距离）
  • 加刚体：给角色加 Rigidbody，运行后角色受重力下落，并稳稳落在地面上（不穿模、不掉下去）
  • 加碰撞体：给角色加合适的 Collider（记得点"编辑碰撞器"调整边框包裹模型）；地面本身就是碰撞体
  • 参数可调：把跳跃冲量 jumpForce 用 public 暴露到 Inspector，能现场调跳多高

核心要求

  • 跳跃用刚体冲量：按空格时用 rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse)，不是直接改 transform.position
  • 落地判定：用 OnCollisionEnter 记住"是否站在地面"，只有站地面时才能起跳——空中不能连跳
  • 撞不翻：给角色的刚体加上 Constraints → 冻结旋转的 X 和 Z，撞到物体或平台侧面时角色不会翻倒

本次作业（必做）：蓄力跳

把"按一下跳固定高度"改成按住空格蓄力、松开才起跳——按得越久跳得越高。长按最多蓄满 1.5 秒，蓄满时跳跃冲量约为原来的 2 倍。

先加两个变量：public float maxCharge = 1.5f;（蓄满要多久）、private float chargeTime = 0f;（现在蓄了多久），再把原来"按空格就跳"的那段换成下面这段：

CSHARP
// ① 蓄力：站在地面上按住空格，时间一帧一帧攒起来（攒到 maxCharge 就不再涨）
if (Input.GetKey(KeyCode.Space) && isGrounded)
{
    chargeTime += Time.deltaTime;
    chargeTime = Mathf.Min(chargeTime, maxCharge);
}

// ② 起跳：松开空格的那一刻才起跳，蓄得越久冲量越大
if (Input.GetKeyUp(KeyCode.Space))
{
    if (isGrounded)
    {
        float force = jumpForce * (1f + chargeTime / maxCharge);
        rb.AddForce(Vector3.up * force, ForceMode.Impulse);
        isGrounded = false;   // 已离地，空中不能再跳
    }
    chargeTime = 0f;          // 不管跳没跳成，蓄力都清零
}

要看到的效果：轻点空格是小跳，按住不放再松开是大跳；在半空中按下空格不生效（还是跳不起来）。

挑战（选做）

  • ① 跳远：起跳时同时给角色一个水平方向的冲量，让它边跳边往前（提示：把 Vector3.up 换成 Vector3.up + 水平方向 再 AddForce）。
  • ② 弹性地面：给地面换一个高弹性的物理材质（Material），角色落地会被弹起来。
  • ③ 二段跳：让角色在半空中还能再跳一次（提示：用一个变量记住"还剩几次"，起跳就减 1、落地时补满，判断条件从"是否站在地面"换成"是否还有次数"）。
⚠️ 改了脚本里 public 变量的默认值，场景里已挂的组件不会跟着变（Inspector 里还是旧值）。把该脚本组件移除后重新添加，或点组件右上角 ⋮ → Reset，新值才会生效。
